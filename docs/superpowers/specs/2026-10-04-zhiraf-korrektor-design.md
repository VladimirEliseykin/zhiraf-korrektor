# Жираф.Корректор — окно программы

Дата: 2026-10-04. Статус: на согласовании.

## 1. Зачем

Сотрудники пишут служебные документы (приказы, распоряжения, служебные записки, отчёты,
справки, техническая документация, письма) и тратят много времени, вручную выискивая опечатки,
неверные окончания и пропущенные запятые. Программа находит их сама и показывает так, чтобы
человек разбирал пометки за секунды, не перечитывая документ целиком.

**Критерий успеха:** сотрудник вставляет или открывает документ, проходит по пометкам клавиатурой
(← → Enter), принимает или пропускает каждую и получает исправленный документ с нетронутым
оформлением.

Движок проверки уже готов и измерен (`engine/spellcheck`, замер `train/engine_eval.py`):
на 3100 предложениях реальных документов исправляет сам 28% ошибок при 0,7 ложных на
100 предложений и подсвечивает «проверьте» ещё 21% при 2,6 ложных. Эта спецификация — про окно
вокруг движка.

## 2. Ограничения

- Windows 7 x64 SP1 без обновлений, от 4 ГБ памяти, без прав администратора, без интернета.
- Документы секретные: **ни одной строки сетевого кода**, текст документов не пишется на диск,
  кроме файлов, которые человек сам сохраняет, и временных копий (раздел 6).
- Встраиваемый Python 3.7.9; весь код совместим с 3.7.
- Скорость вторична, качество важнее; программа должна честно показывать, сколько ждать.
- Без интеграции с Word: всё происходит в окне программы.

## 3. Состав

```
Жираф.Корректор/                    одна папка, копируется с флешки
  Жираф.Корректор.exe               маленький запускатель с иконкой (pythonw + app)
  python/                           встраиваемый Python 3.7.9 + библиотеки
  vcruntime140.dll, msvcp140.dll …  Visual C++ рядом с программой (на голой Win7 их нет)
  engine/spellcheck/                движок (готов)
  app/                              окно (новое)
  models/{sage,commas,forms,vocab.tsv}
  art/start.jpg, art/logo.png
```

Библиотеки окна: PySide2 5.15.2.1 (Qt 5.15 поддерживает Windows 7, LGPL), lxml 4.9 (правка
.docx/.odt без порчи XML), python-docx (создание нового .docx из вставленного текста),
comtypes (Word через COM для .doc). Всё — колёса cp37 win_amd64 или чистый Python.

### Модули окна (`app/`)

| Модуль | Отвечает за |
|---|---|
| `main.py` | запуск, окно, меню, горячие клавиши |
| `start_screen.py` | стартовый экран: картинка, кнопки, перетаскивание, недавние документы |
| `editor.py` | область текста: подсветка пометок, курсор текущей пометки, зелёные/серые отметки |
| `card.py` | широкая карточка пометки: исправление, объяснение, кнопки, «исправить вручную» |
| `status.py` | счётчики (ошибки, проверить, исправлено, пропущено), «Принять все ошибки (?)», прогресс |
| `worker.py` | процесс проверки: этапы, поток пометок, оценка времени, остановка |
| `segment.py` | деление абзацев на предложения с позициями |
| `documents/model.py` | общая модель документа: абзацы → прогоны текста с оформлением и позициями |
| `documents/docx.py`, `odt.py` | чтение в модель и сохранение «на месте» |
| `documents/doc.py` | .doc через Word (COM) → LibreOffice → извлечение текста |
| `documents/clipboard.py` | вставка из буфера с оформлением, «Скопировать с оформлением» |
| `documents/export.py` | «Сохранить как»: .docx, .odt, .pdf, .txt |
| `storage.py` | словарь, настройки, недавние документы (профиль пользователя) |

Каждый модуль документа отдаёт одно и то же: список абзацев с текстом и картой «символ абзаца →
место в исходном файле». Окно и проверка работают только с этой моделью и не знают о форматах.

## 4. Окно

### Стартовый экран
Слева — иллюстрация (жираф в куртке «ИБ» у стены-файрвола, хакер с удочкой, приманка
«Премия.pdf.exe» со штампом «ФИШИНГ») во всю высоту; её ночное небо продолжается фоном окна.
Справа: «Проверим документ на ошибки?», подзаголовок «…текст никуда не отправляется», кнопки
«Вставить текст» (Ctrl+V) и «Открыть документ» (Ctrl+O · .docx, .doc, .odt), зона
перетаскивания, «Недавние документы» (значок формата, имя, папка, дата, итог «✓ 12 исправлено,
3 пропущено» или «разобрано 14 из 23», ссылка «Очистить список»; список прокручивается),
внизу закреплённая строка «F1 — горячие клавиши · Работает без интернета».
Других картинок и анимаций нет: в конце проверки прогресс показывает 100%.

### Главное окно (вариант B из макетов)
- Заголовок: логотип-шар, «Жираф.Корректор — имя файла».
- Панель: «Открыть», «Вставить», «Остановить» (во время проверки), «Сохранить ▾».
- Справа вверху — прогресс: «Проверено 42% · осталось ≈ 4 мин · готово к 18:52»,
  синяя полоса со светящейся «луной» на конце.
- Текст на «бумаге». Пометки:
  - ошибка — кирпичная заливка и сплошное подчёркивание;
  - проверьте — жёлтая заливка и пунктир;
  - исправлено — зелёная заливка, при наведении «было: …»;
  - пропущено — серая заливка и подпись «пропущено»;
  - ещё не проверенный текст — бледный, «ещё проверяется».
- Карточка текущей пометки — широкая и низкая: слева иконка, тип, «по ~~доступ~~ → по
  доступу»; справа объяснение; снизу «Принять (Enter)», «Пропустить», «В словарь»
  (только у пометок о написании слова), «Исправить вручную» (поле для своего варианта),
  подсказки ← → и Ctrl+Z.
- Строка состояния: иконки одного стиля (SVG), текст цвета иконки — ✕ ошибки, ⚠ проверить,
  ✓ исправлено (галочка в кружке), ↷ пропущено (серая); справа неубираемая кнопка
  «Принять все ошибки (?)» с подсказкой «Исправит все ошибки (сейчас N). Пометки «проверить»
  останутся».

Палитра — из иллюстрации: ночное небо `#56708f`, бумага `#f6f3ec`, чернила `#26303b`, лунный
свет `#fbf7e9`, ошибка `#b9524a`, проверьте `#d9a521`, исправлено `#3f9a4e`, пропущено `#8792a2`.

### Поведение
- ← / → — к предыдущей/следующей неразобранной пометке; Enter — принять.
- После «Принять», «В словарь», «Пропустить» или ручного исправления — автоматически к следующей.
- Ctrl+Z отменяет последнее действие с пометкой (возвращает текст и состояние).
- «Принять все ошибки» применяет только уровень «ошибка»; отменяется одним Ctrl+Z.
- Вставленный текст можно свободно править. В открытом документе печатать нельзя (иначе файл
  пришлось бы пересобирать); изменения вносятся только через пометки и «Исправить вручную».
- F1 — окно со списком клавиш.

## 5. Проверка

- Окно и проверка — разные процессы: окно не подвисает, память модели освобождается после этапа.
- Этапы по пользе на секунду: правила (мгновенно) → запятые (~0,1 с/предл.) → окончания
  (~0,1 с/предл.) → SAGE (~0,5 с/предл.). Модели загружаются по одной (пик ~1,2 ГБ).
- Пометки приходят по мере готовности и появляются в тексте сразу; разбирать можно с первой
  секунды. Пометка для места, которое человек уже изменил, отбрасывается.
- Прогресс = доля выполненной работы, взвешенная по скорости этапов; время до конца — по
  фактической скорости на этом компьютере, уточняется по ходу.
- «Остановить» прерывает проверку, найденное остаётся.
- Изменённые человеком абзацы вставленного текста перепроверяются после основного прохода.
- Объединение пометок, уровни и пороги — как в `engine/spellcheck/checker.py`.
- Слова из словаря пользователя не подсвечиваются ни одним правилом и ни одной моделью.

## 6. Документы

### Вставка (Ctrl+V)
Из буфера берётся HTML (абзацы, заголовки, жирный, курсив, подчёркивание, списки, простые
таблицы); картинки не переносятся. «Скопировать с оформлением» кладёт исправленный текст в буфер
как HTML и как простой текст. «Сохранить как…»: .docx, .odt, .pdf, .txt.

### .docx и .odt
- Показ: абзацы, заголовки, начертание, списки, таблицы; картинки — значок «рисунок».
- Проверяется основной текст и таблицы (колонтитулы и сноски — следующая версия).
- Сохранение «на месте»: берётся исходный файл, в XML меняются только символы принятых
  исправлений; если исправление пересекает несколько прогонов текста, новый текст пишется в
  первый прогон, остальные укорачиваются; всё остальное (стили, колонтитулы, поля, картинки)
  остаётся байт в байт.
- Новый файл «Имя (исправлено).docx» рядом с исходным; **оригинал никогда не перезаписывается**.

### .doc
1. Есть Word → через COM (comtypes) открыть невидимо, сохранить временную копию .docx,
   работать как с .docx, сохранить результат обратно в .doc тем же Word.
2. Нет Word, есть LibreOffice → то же через `soffice --headless --convert-to`.
3. Нет ни того, ни другого → извлечь текст без оформления; сохранить исправленную версию можно
   только как .docx, о чём программа говорит прямо.

### Временные файлы
Только в `%LOCALAPPDATA%\Жираф.Корректор\tmp`, удаляются сразу после работы и при каждом
запуске (на случай аварийного закрытия).

## 7. Словарь, настройки, недавние документы
Всё в `%APPDATA%\Жираф.Корректор\`:
- `словарь.txt` — одно слово на строку, без предложений; окно словаря (список, поиск,
  удаление), «Выгрузить…» / «Загрузить…» (слова объединяются).
- Настройки: «Показывать пометки «проверьте»» (вкл.), «Строгий режим: заглавные буквы посреди
  предложения» (выкл.), «Запоминать недавние документы» (вкл.).
- Недавние документы: путь, дата, итоговые счётчики; ни текста, ни найденных ошибок.

## 8. Запуск и поставка
- Одна папка (~2,3 ГБ), копируется куда угодно; «Жираф.Корректор.exe» с иконкой-шаром.
- Без установщика, без прав администратора, без обновлений Windows (Visual C++ рядом с
  программой).
- При первом запуске — предложение создать ярлык на рабочем столе.
- Сборка папки — скриптом на Linux; ISO для проверки в виртуальной машине Windows 7.

## 9. Безопасность
- Сборка проверяет, что в папку не попали сетевые модули (`socket`, `ssl`, `urllib`, `http`,
  `QtNetwork`, …) и что код программы их не импортирует; при нарушении сборка падает.
- Журнал ошибок — только технические сведения (тип ошибки, место в коде), без текста документов.

## 10. Ошибки
- Файл не открылся (повреждён, защищён паролем, неизвестный формат) — понятное сообщение,
  программа остаётся на стартовом экране.
- Нехватка памяти или сбой процесса проверки — найденное остаётся, сообщение «Проверка
  прервана» с кнопкой «Продолжить с этого места».
- Нет файлов моделей — сообщение при запуске, какой папки не хватает.
- Сохранение не удалось (нет прав, файл открыт в Word) — сообщение и «Сохранить как…».

## 11. Проверка качества
- Модульные тесты: деление на предложения; карта позиций; чтение и сохранение .docx/.odt
  (после принятия исправлений текст файла равен ожидаемому, а XML вне исправлений не изменился);
  объединение пометок; словарь; оценка времени.
- Движок — существующий замер `train/engine_eval.py` на 3100 предложениях.
- Сквозная проверка в виртуальной машине Windows 7 (4 ГБ): запуск без прав администратора,
  вставка, открытие .docx/.doc/.odt, сохранение, память и время.
- Сборка проверяется на отсутствие сетевого кода (раздел 9).

## 12. Не входит в эту версию
Интеграция с Word (рецензирование, надстройки), колонтитулы и сноски, картинки во вставке,
проверка папки документов, автообновление.

## 13. Связанные работы
Идёт переобучение моделей с правильным токенизатором и крупные модели (ruBERT-large). Новые
модели подключаются заменой папок `models/commas` и `models/forms` после замера; у ruBERT-large
нужно отдельно выяснить лицензию до включения в поставку.
